# 디자인 브리프 & 프롬프트 (Claude Design 전달용)

> Claude Design(또는 디자인 협업 AI)에 **디자인 시스템·UIUX 제작**을 요청할 때 그대로 복붙해 쓰기 위한 문서.
> 화면별 상세는 중복 서술 없이 각 화면 명세를 링크로 참조한다. 실제 요청 시 해당 화면 문서를 함께 첨부하는 것을 권장.

---

## A. 서비스 특성 요약 (모든 프롬프트 공통 전제)

```
[제품] RunDiary — 러닝 일지·컨디션 기록 iOS 앱 (iOS 18+, SwiftUI)
[핵심 가치] 정량 데이터(HealthKit: 거리·심박·케이던스·파워·경로·시계열)와
           감성 회고(통증·주법·난이도·메모·날씨 체감)를 한 기록에 결합.
[톤&무드] 러닝의 성취감 + 개인적 회고. 데이터는 명료하게, 회고는 따뜻하게.
[제약]
- 라이트 모드 고정 (다크 모드 없음).
- 한국어 기본, 영어/일본어 지원 (텍스트 길이 가변 → 잘림 주의).
- 컬러: Claude Design이 제안하는 팔레트를 기본으로 따른다.
  단, 다음 3색은 기존 브랜드 자산으로 유지·반영: blue_300(#4F48EC) / yellow_100(#FFBF18) / coral(#FF6B6B)
- 타이포그래피: 자체 토큰 체계나 지정 폰트 없음.
  Claude Design이 명세하는 타이포 시스템(기본 시스템 폰트 기준)을 우선으로 따른다.
```

## B. 디자인 시스템 요청 프롬프트

```
당신은 iOS 디자인 시스템 아키텍트다. 위 "서비스 특성 요약"을 전제로,
RunDiary의 라이트 모드 전용 디자인 시스템을 설계해 달라.

요청 산출물:
1) 컬러 시스템
   - 팔레트는 네가 제안하되, 다음 3색은 기존 브랜드 자산으로 반드시 유지·반영한다:
     blue_300 / yellow_100 / coral.
   - 위 3색을 포함해 전체 팔레트를 의미 토큰
     (background/surface/textPrimary/textSecondary/divider/accent/warning/success 등)으로 매핑.
   - 러닝 데이터 시각화용 카테고리 컬러(심박/페이스/케이던스/고도 등 지표별 구분색) 제안.
   - 접근성 대비(WCAG AA) 충족 여부 명시.
2) 타이포그래피 스케일
   - 자체 토큰이나 지정 폰트가 없으므로, 기본 시스템 폰트 기준으로 스케일을 제안한다.
   - display/title/headline/body/caption 등 역할별 크기·굵기·행간.
   - 정량 수치(숫자 강조)와 본문·메모 텍스트의 역할 구분.
   - Dynamic Type 대응 원칙.
3) 핵심 컴포넌트 토큰
   - 카드(요약/상세), 선택 칩(SelectableChip), 주요/보조 버튼,
     차트(라인/막대), 지표 타일, 리스트 로우, 프로그레스.
   - 각 컴포넌트의 여백·라운드·그림자·상태(default/selected/disabled) 토큰.
4) 간격·라운드·엘리베이션 스케일(4pt 그리드 기준 제안).

제약: 라이트 모드만. 한/영/일 가변 텍스트를 견디는 레이아웃 원칙 포함.
```

## C. 화면별 UIUX 제작 프롬프트

각 블록은 독립적으로 사용 가능하다. 사용 시 해당 화면 명세 문서를 함께 첨부하라.

### C-01. 로그인 → [명세](./01-login.md)
```
로그인 화면을 디자인해 달라.
- 구성: 브랜드 타이틀("달림일기"), Apple 로그인 버튼(HIG 고정 형태), 로딩/에러 상태.
- 목적: 감성적 러닝 앱의 첫인상. 로고·서브카피·배경 무드 제안 환영.
- 제약: Apple 버튼 형태는 커스텀 불가(주변 여백·문구만). 사용자 취소는 에러로 취급 안 함.
- 상태: 기본 / 로딩 / 에러(빨강 텍스트) 3종.
```

### C-02. 주간 기록 허브 (메인) → [명세](./02-daily-detail.md)
```
메인 화면(주간 러닝 기록 허브)을 디자인해 달라.
- 구성: 상단 연월 헤더(+설정 톱니), 주 단위 날짜 캐러셀(스와이프), 선택일 기록 목록.
- 카드는 "요약"만: 시각 + 거리/시간/평균 페이스 + 난이도·만족도 힌트 (상세는 별도 화면으로 이동).
- 미작성 워크아웃 카드(일기 작성 유도)와 빈 상태도 디자인.
- 정보 위계: 날짜 탐색(1차) → 기록 카드(1차) → 날씨 출처(보조).
- UX 의도: 빠르게 훑는 목록. 오늘/선택/기록유무의 시각 구분이 핵심.
```

### C-03. 월간 캘린더 시트 → [명세](./03-calendar.md)
```
월간 캘린더(시트)를 디자인해 달라.
- 구성: 오늘 버튼(조건부 활성), 수직 무한 스크롤 월간 달력, 하단 "일기 보기" 버튼.
- 셀: 일자 + 그 날 총 거리 + 상태색(오늘/일요일/선택) + 미작성 워크아웃 coral 점.
- 헤더: 연월 + 그 달 총 거리.
- UX 의도: 총 거리로 러닝량을 한눈에, 색/점으로 기록 유무 구분.
```

### C-04. 일기 작성 위저드 (7단계) → [명세](./04-create-diary.md)
```
일기 작성 7단계 위저드를 디자인해 달라.
- 스텝: 운동요약 → 날씨체감 → 신발 → 주법 → 통증부위 → 난이도 → 메모.
- 공통: 스텝 인디케이터, 이전/다음/저장 하단 바(스텝별 진행 검증).
- 특수 인터랙션: 통증부위 신체 이미지 + 탭 리플, 난이도 드래그 막대,
  날씨 체감 칩 4그룹(하늘/바람/체감/습도), 신발 2단(브랜드+모델).
- UX 의도: 한 화면 한 결정으로 기록 부담 최소화. 필수(신발·주법·난이도) vs 선택 구분.
```

### C-05. 설정 → [명세](./05-settings.md)
```
설정 화면을 디자인해 달라.
- 현재: 개인정보처리방침/이용약관 링크(리스트 로우 + chevron).
- 향후 확장 대비: 계정/로그아웃, 데이터 관리(마이그레이션) 섹션 자리 고려.
- 표준 iOS 설정 리스트 관습 유지.
```

### C-06. 일기 상세 화면 (신규·핵심) → [명세](./06-record-detail.md)
```
일기 상세 화면을 새로 디자인해 달라. 이 화면이 이번 리디자인의 하이라이트다.
- 벤치마크: Apple 피트니스 / Strava의 운동 상세. 데이터 몰입형.
- 정보 구조(위→아래): 요약 헤더 → 시계열 그래프(심박/페이스/케이던스/고도 탭 전환)
  → 구간 스플릿(랩 분석) → 경로 지도 → 상세 지표 그리드 → 감성 회고(통증/주법/난이도/메모).
- 차트: 시간축 라인 차트, 지표별 카테고리 컬러. 구간은 표 또는 막대(최속/최저 강조).
- UX 의도: 정량은 차트로 몰입, 하단 메모는 여백+세리프로 톤 전환. 접기/펼치기로 점진적 개시.
- 데이터는 이미 존재(WorkoutSeries/WorkoutSplit/route/지표) — 시각화 설계에 집중.
```

### C-07. 마이그레이션 로딩 (신규) → [명세](./07-migration-loading.md)
```
로컬→서버 데이터 이전 중 표시할 전체화면 로딩/전환 화면을 디자인해 달라.
- 구성: 안심 일러스트/카피("기록을 안전하게 옮기고 있어요"),
  결정적 진행률(N/M개) 또는 단계 인디케이터(준비→업로드→검증→완료),
  "앱을 닫지 말아 주세요" 안내, 실패 상태(사유 + 다시 시도).
- UX 의도: 서버 전환 후 첫 경험 → 신뢰감. 러닝 감성과 이어지는 톤.
- 상태: 진행 중 / 성공 전환 / 실패(재시도) 3종.
```

## D. 사용 팁
두 가지 진행 경로가 있다. 상황에 맞게 택1.
- **경로 1 (시스템 우선)**: **E의 통합 블록**을 먼저 붙여 디자인 시스템을 확정한 뒤, 화면 프롬프트(C)를 하나씩 진행. 일관성이 가장 높다.
- **경로 2 (화면 일괄)**: **F의 통합 블록**으로 전체 7화면을 한 번에 생성한 뒤, 필요한 부분만 상위 모델로 수정·정리. 토큰을 아끼며 빠르게 전체 윤곽을 잡을 때. 디자인 시스템은 생성된 화면에서 자연히 도출/정리한다.
- (공통) 화면 프롬프트 사용 시 해당 화면 명세 문서를 첨부하면 정보 위계·상태 분기까지 정확히 전달된다.
- (공통) 신규 화면(06/07)은 참고 이미지(피트니스 앱 스크린샷 등)를 함께 주면 벤치마크 방향이 명확해진다.

## E. 복붙용 최종 프롬프트 (디자인 시스템 생성)

> claude.ai/design 에 **한 번에 붙여넣는** 통합 프롬프트. 위 A(서비스 요약) + B(요청 산출물)를 자기완결적으로 병합한 버전이다. A·B는 학습·참고용으로 존치한다.

```
당신은 iOS 디자인 시스템 아키텍트다. 아래 제품을 위한 라이트 모드 전용 디자인 시스템을 설계해 달라.

[제품] RunDiary — 러닝 일지·컨디션 기록 iOS 앱 (iOS 18+, SwiftUI)
[핵심 가치] 정량 데이터(HealthKit: 거리·심박·케이던스·파워·경로·시계열)와
           감성 회고(통증·주법·난이도·메모·날씨 체감)를 한 기록에 결합.
[톤&무드] 러닝의 성취감 + 개인적 회고. 데이터는 명료하게, 회고는 따뜻하게.
[제약]
- 라이트 모드 고정 (다크 모드 없음).
- 한국어 기본, 영어/일본어 지원 → 텍스트 길이 가변, 잘림에 견디는 레이아웃.

요청 산출물:

1) 컬러 시스템
   - 팔레트 전체는 네가 제안한다. 단 아래 3색은 기존 브랜드 자산이므로
     정확히 이 값·역할로 반드시 팔레트에 포함하라:
       · blue_300  → 주 accent(강조/선택/주요 액션) 계열
       · yellow_100 → 보조 강조(하이라이트/배지)
       · coral     → 경고 및 "미작성 워크아웃" 표식
   - 위 3색을 제외한 배경/서피스/텍스트/디바이더 등 나머지 색은
     네가 제안하는 팔레트로 자유롭게 구성해도 된다.
   - 전체 색을 의미 토큰(background/surface/textPrimary/textSecondary/
     divider/accent/warning/success 등)으로 매핑.
   - 러닝 데이터 시각화용 카테고리 컬러(심박/페이스/케이던스/고도 등 지표별 구분색) 제안.
   - 접근성 대비(WCAG AA) 충족 여부 명시.

2) 타이포그래피 스케일
   - 지정 폰트·자체 토큰 체계 없음. 기본 시스템 폰트(SF Pro 계열) 기준으로 스케일을 제안하라.
   - display/title/headline/body/caption 등 역할별 크기·굵기·행간.
   - 정량 수치(숫자 강조)와 본문·메모 텍스트의 역할 구분. (세리프 강제 아님)
   - Dynamic Type 대응 원칙.

3) 핵심 컴포넌트 토큰
   - 카드(요약/상세), 선택 칩(SelectableChip), 주요/보조 버튼,
     차트(라인/막대), 지표 타일, 리스트 로우, 프로그레스.
   - 각 컴포넌트의 여백·라운드·그림자·상태(default/selected/disabled) 토큰.

4) 간격·라운드·엘리베이션 스케일 (4pt 그리드 기준 제안).

제약 재확인: 라이트 모드만. 한/영/일 가변 텍스트를 견디는 레이아웃 원칙 포함.

## F. 복붙용 최종 프롬프트 (전체 화면 일괄 생성)

> claude.ai/design 에 **한 번에 붙여넣어 7화면 전체를 일괄 생성**하는 통합 프롬프트. A 공통 전제 + 화면별 [구성/데이터/인터랙션/상태]를 자기완결적으로 담았다. 생성 후 다듬기는 상위 모델(예: Opus)로 진행한다.
> 신규 화면(06 일기 상세, 07 마이그레이션)은 참고 이미지(Apple 피트니스·Strava 스크린샷)를 함께 첨부하면 좋다.

```
당신은 iOS 프로덕트 디자이너다. 아래 러닝 일지 앱 RunDiary의 전체 화면(7개)을
하나의 일관된 디자인 시스템·플로우로 설계해 달라. 각 화면은 [구성]/[데이터]/[인터랙션]/[상태]를 만족해야 한다.

[제품] RunDiary — 러닝 일지·컨디션 기록 iOS 앱 (iOS 18+, SwiftUI)
[핵심 가치] 정량 데이터(HealthKit: 거리·심박·케이던스·파워·경로·시계열)와
           감성 회고(통증·주법·난이도·메모·날씨 체감)를 한 기록에 결합.
[톤&무드] 러닝의 성취감 + 개인적 회고. 데이터는 명료하게, 회고는 따뜻하게.
[공통 제약]
- 라이트 모드 고정 (다크 모드 없음).
- 한국어 기본, 영어/일본어 지원 → 텍스트 길이 가변, 잘림에 견디는 레이아웃.

■ 01. 로그인

- [인터랙션] 날짜 탭(선택), 좌우 스와이프(주 이동), 연월 탭→캘린더 시트, 톱니 탭→설정, 요약 카드 탭→일기 상세(06), 미작성 카드 "일기 작성" 탭→작성 위저드(04), 당겨서 새로고침.
