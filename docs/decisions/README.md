# Decisions — 작업 기록

되돌리기 어려운 판단을 남기는 곳이다. 한 작업 단위에 파일 하나를 두고, **착수 전에 절반을 쓰고 완료 후에 나머지 절반을 쓴다.**

## 왜 두 번에 나눠 쓰는가

에이전트에게 구현을 맡기려면 "무엇을 왜 그렇게 만들 것인가"가 착수 전에 글로 있어야 한다. 그것이 **Ⅰ. 착수 전**이다.

그런데 착수 전 판단은 자주 틀린다. 무엇이 어떻게 틀렸는지를 남기지 않으면 다음 작업에서 같은 방식으로 또 틀린다. 그것이 **Ⅱ. 완료 후**다.

> **Ⅰ은 완료 후에 고치지 않는다.** 틀린 예측은 지우지 말고 Ⅱ에 "여기서 틀렸다"로 적는다.
> 예측을 사후에 정답으로 덮으면 기록이 항상 옳아 보이고, 그 기록에서는 아무것도 배울 수 없다.

## 언제 쓰는가

**쓴다** — 다음 중 하나라도 해당할 때.

- 스키마·전송 계약처럼 나중에 바꾸려면 마이그레이션이나 상대 팀 협의가 필요한 것
- 명백한 선택지 둘 이상에서 하나를 고른 것 (고르지 않은 쪽의 이유가 사라지면 다음 사람이 다시 고민한다)
- 외부와 합의한 것 (백엔드 계약, 서드파티 동작)
- 기존 방식을 의도적으로 어긴 것

**쓰지 않는다** — 리팩터링, 버그 수정, 컨벤션대로의 구현. 커밋 메시지로 충분하다.

## 무엇을 쓰지 않는가

**코드·테스트·git으로 복원 가능한 것은 쓰지 않는다.** 경로와 커맨드로만 참조한다.

| 쓰지 않는다 | 이유 |
|---|---|
| 진행 상태표(`✅ 완료` / `⏳ 미착수`) | 코드가 이미 답이다. 문서만 낡는다 |
| 파일 목록·시그니처·필드 표 | 코드가 정본이다. 두 벌이 되면 어느 쪽이 참인지 알 수 없다 |
| 테스트 케이스 목록 | 테스트 파일이 정본이다 |
| 구현 절차 | 계획은 계획대로 안 간다. 판단과 그 근거만 남는다 |

이 규칙은 `.handoff/`의 원칙과 같다. 앞선 `docs/api/create-diary-client-implementation-spec.md`가 상태표와 TC 목록을 안고 있다가 절반이 낡아 폐기된 것이 이 규칙이 생긴 이유다.

## 파일

`docs/decisions/NNNN-슬러그.md` — 번호는 순번이다. 이슈 번호를 쓰지 않는 이유는 하나의 결정이 여러 이슈에 걸치기 때문이다. 관련 이슈는 문서 안에 적는다.

## 상태

머리말에 하나를 적는다.

| 상태 | 뜻 |
|---|---|
| `착수 전` | Ⅰ만 작성됨. 구현 대기 |
| `구현 중` | Ⅰ 확정, Ⅱ 미작성 |
| `완료` | Ⅱ까지 작성됨 |
| `폐기` | 구현하지 않기로 함. **지우지 말고 폐기 사유를 Ⅱ에 남긴다** |

## 템플릿

```markdown
# NNNN. 제목

> 상태: 착수 전 · 이슈 #N · YYYY-MM-DD

## Ⅰ. 착수 전

### 문제
무엇이 없거나 잘못돼 있는가. 지금 손대지 않으면 무엇이 곤란해지는가.

### 결정
결정마다 한 절. **고르지 않은 쪽과 그 이유를 반드시 함께 적는다.**

### 예상 위험
틀릴 수 있다고 보는 지점. 여기가 Ⅱ에서 대조할 자리다.

### 미결
착수 시점에 답이 없는 것과, 답 없이 어떻게 진행하는지.

---

## Ⅱ. 완료 후

> 완료일 · 커밋 범위

### 맞은 예측 / 틀린 예측
Ⅰ의 "예상 위험"과 하나씩 대조한다.

### 구현 중 드러난 것
착수 전에는 몰랐던 것. **다음 작업에 그대로 쓰일 지식이 여기 모인다.**

### 남은 부채
```

## 다른 문서와의 관계

| 문서 | 무엇을 담는가 |
|---|---|
| `docs/api/` | 상대 팀과 공유하는 **계약 정본.** 서버도 같은 문서를 본다 |
| `docs/product/` | 화면과 사용자 경험의 의도 |
| `docs/specs/issue-{N}/` | 명세-우선 테스트 재작성의 TC 매트릭스 |
| `docs/decisions/` | **왜 그렇게 만들기로 했는가**와 그 판단이 맞았는지 |
| `.handoff/CURRENT.md` | 지금 세션의 이어받기 노트. 작업이 끝나면 사라진다 |

결정 기록은 계약 정본을 복사하지 않는다. 계약이 왜 그 모양인지만 적고 정본을 링크한다.
